# V1.2.1 整机验证前的联调范围

五种已确认玩法作为验收范围。整理后的用户手册和旧 Node 实现用于校对 AI 的职责。手册中的手机号或微信登录、邀请密码、实时字幕、语气提示及新增玩法需要单独定范围。当前同机亲子练沿用已确认的体验，正式面向未成年人开放前需补齐监护同意和数据管理。

## 当前版本与验收差距

| 位置 | 当前实现 | 整机验证前要求 |
| --- | --- | --- |
| 四种房间玩法的语音处理 | 使用火山录音识别；方舟负责根据确认的要点对照复述，并核验引用 | 在隔离环境逐个跑通真实链路。模型只提供辅助判断，无法使用模型时明确显示降级来源 |
| 表达要点 | 本地 Java 从表达转写抽取候选并核验原句，只向当轮表达者返回 | 在预发布用授权素材校验候选命中、手动调整和权限，再切换生产 |
| 改写建议 | 本地 Java 根据已确认差异为各角色生成建议，记录对应条目和来源；模型不可用时使用规则建议 | 用真实方舟验证各角色输出、失败降级和确认结果的一致性 |
| 单人练习 | 本地改版去除了示例复述、手填成绩和前端提交分数 | 玩家始终为复述者。本人授权上传后，服务端转写实际录音并与素材库原录音逐句对照，通过分析 ID 归档。无语音或失败时停留在当前步骤 |
| 历史身份 | 昵称绑定当前会话，房间通过邀请与成员角色授权。主动退出后旧会话立即失效 | 继续允许昵称体验。需跨设备访问或管理个人历史时，由 Spring Security 接入已配置的 OIDC 身份服务，按已验证主体归属数据 |
| 数据保存 | Java 使用私有 S3 兼容存储、短期签名、加密文本及成员隔离 | 验证存储和备份静态加密、删除和访问失效、保留期限、素材授权范围、密钥恢复及操作审计 |

## 执行顺序

1. **业务规则与数据边界**。为每种玩法列出实际音频、转写、模型、最终确认人和报告字段。素材库候选、练习录音、转码临时件分开记录。语音识别只接收用户同意发送的音频，语义模型只收到完成任务所需的文本。模型建议不得替代人类确认；未一致的条目沿用当前玩法计分规则。
2. **真实 AI 与异步处理**。使用已有火山文件转写、方舟 Chat API、Spring Boot 和 MySQL 作业机制。补充模型的结构校验、原句回指、超时、并发限制与失败状态。单人练习再接入服务端处理和可信报告，报告分数由后端归档。为候选和改写分别记录来源和请求计数，短时失败用手动核对或明确的规则建议继续。
3. **身份与资源权限**。访客身份/已验证账号与表达者、复述者、观察者、房主是两套概念。服务端检查房间角色、当前阶段和资源所有权。审查邀请有效期、使用次数、撤销、会话轮换与登出。既有访客数据只有在持有原会话且完成身份验证后才能绑定。亲子同机对孩子的录音分享和历史管理需有监护确认；昵称不作为身份凭据。
4. **删除、备份与恢复**。用 Flyway 交付可回退的增量迁移，先在空库和上一版本备份上演练。私有存储按用途约束上传和签名播放。登记用户删除和授权撤回，联动 MySQL 对象引用、对象存储、未发布候选和备份保留期。用隔离环境实际恢复 MySQL、对象数据及解密密钥，记录恢复耗时和验证结果。
5. **预发布与证据**。继续使用 Vue 和 Spring Boot 的同源 HTTPS 容器。隔离数据库、存储桶、模型凭据和测试账号，避免把测试数据写进生产。GitHub Actions 验证类型检查、Maven、Testcontainers、发布镜像与迁移。Playwright 验证独立会话、异常恢复、权限拒绝和五种玩法。Vercel 可用于受保护的前端预览，前后端分开时另测邀请 URL、Cookie、Origin 和录音上传。
6. **进入整机验证的条件**。五种玩法至少各完成一次用授权录音的端到端联调。正常、识别无语音、供应商失败、断网/重试和错误角色访问均有验收结果。完成删除和恢复演练；记录部署镜像摘要、验收版本、转写/模型来源和回滚步骤。整机验证在这些结果齐备后执行。

## 2026-11-18 发布验证

- 正式候选版使用 Linux 镜像 `echo-java:1.2.1`，摘要 `sha256:0b41295f2e83c0525aa536222605814e436bae8aaf25339e55f02b07d336083b`。Vue、Spring Boot 与实际 AI 链路来自 PR #2 的提交 `d884b25fd8b4cf6ecebcdbf18d919e73d8232c04`，该提交 CI 全部通过。
- VPS 历史数据库已恢复到新卷并升级至 Flyway V17。抽查的 5 组加密转写可用原密钥解密，其对应私有录音经签名访问均返回 200，大小与数据库一致。恢复归档的 SHA256 校验通过。
- 公网正式候选版上，五种玩法均用合成录音通过真实火山识别、方舟对照、角色建议和报告归档。静音返回 `NO_SPEECH`，不生成或归档成绩。
- 重启后在 Windows Edge 的独立浏览器会话验证了合成麦克风捕获、授权上传（202）、真实识别和方舟对照、逐条结论、建议采纳、两个报告播放器、390px/1280px 页面和退出失效（204），未出现页面运行异常。四种房间玩法在重启后也均复测通过，包括亲子下一轮换位和异步留言访问边界。
- 首轮验收出现过转码超时及随后 SSH/HTTPS 无响应，现经用户重启恢复；没有取得足以确认 OOM 的上次启动日志，因此内存耗尽仅作为恢复假设。VPS 已新增并持久化 2 GiB 交换空间，应用仍采用容器内存限制。VPS 上的重型浏览器安装不再继续，浏览器验收在已有电脑环境完成；本地网络、代理和动态端口设置未变更。
- 发布及旧部署清理的实际进度、备份保留位置和最终空间结果见 [执行记录](../deploy/V1.2.1-CUTOVER-REVIEW.md)。以下保留此前轮次的验证记录，不代表最终镜像和当前待办状态。
